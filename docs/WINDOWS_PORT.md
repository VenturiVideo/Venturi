# Porting Venturi to Windows

This fork ports Venturi, developed and tested on Linux, to Windows 11 x64. The
editor builds with the MSVC toolchain, runs natively, and keeps every feature
of the Linux build: GPU compositing, hardware decoding and encoding, VST3
plugins and the MCP server, including attach mode.

The changes are additive. Linux and macOS take the same code paths as before;
Windows gets its own behind `cfg(windows)`.

## Download

Get `Venturi-x86_64-windows.zip` from the
[Releases](https://github.com/baleight/Venturi/releases) page, unpack it
anywhere and run `venturi.exe`. FFmpeg's DLLs ship next to the executable;
nothing else needs installing. A GPU driver with Vulkan or Direct3D 12 is
required, as on every recent Windows machine.

The build is unsigned, so the first launch may show Windows SmartScreen:
**More info → Run anyway**.

## What changed

### Building on Windows

Most of the code was already portable; one call did not compile:
`hw_decode::default_budget_bytes` read the physical memory through `sysconf`,
which Windows lacks. It now uses `GlobalMemoryStatusEx`. `libc` became a
Unix-only dependency.

FFmpeg's bindings are generated by `bindgen`, which needs `libclang` and the
MSVC C headers. Three PowerShell scripts take care of that:

| Script | What it does |
|---|---|
| `scripts\install-windows-deps.ps1` | Installs Rust, the Visual Studio 2022 Build Tools (C++), LLVM and a shared GPL FFmpeg 9.0 build, skipping what is there |
| `scripts\windows-env.ps1` | Dot-sourced once per terminal: sets `FFMPEG_DIR`, `LIBCLANG_PATH`, `INCLUDE` and `PATH` |
| `scripts\build-windows.ps1` | Builds the release and packs `target\windows\Venturi-x86_64-windows.zip` |

The executable embeds the Venturi icon (`winresource`). Release builds use
the Windows GUI subsystem, so opening `venturi.exe` shows no console window;
started from a terminal, it borrows that terminal's console, so `venturi mcp`
and the logs still print there.

### Where data lives

A new `vv_core::dirs` module answers "where do settings, data and caches go"
for the whole workspace, replacing five copies of XDG lookups:

| | Linux | Windows |
|---|---|---|
| Settings | `$XDG_CONFIG_HOME/venturi` | `%APPDATA%\venturi` |
| Library | `$XDG_DATA_HOME/venturi/library` | `%APPDATA%\venturi\library` |
| Proxies, waveforms, levels | `$XDG_CACHE_HOME/venturi` | `%LOCALAPPDATA%\venturi` |

### Hardware decoding: Direct3D 11

Settings → Playback offers **Direct3D 11 (D3D11VA)** besides NVDEC and Vulkan
video. It decodes on any GPU (Intel, AMD, NVIDIA) through the Windows video
driver. On Windows, **Automatic** tries NVDEC first on NVIDIA GPUs, then
D3D11VA, then Vulkan video, which fewer Windows drivers support.

Export keeps x264, NVENC and Vulkan encode.

### VST3 plugins

- **Scan**: `%COMMONPROGRAMFILES%\VST3` and `%LOCALAPPDATA%\Programs\Common\VST3`,
  the folders of the VST3 specification.
- **Loading**: bundles (`Plugin.vst3\Contents\x86_64-win\Plugin.vst3`) and
  older single-file `.vst3` DLLs, with the optional `InitDll`/`ExitDll` entry
  points. DLLs a plugin ships next to its binary are found.
- **Editor**: a native Win32 window hosts the plugin's HWND view. User
  resizes reach the plugin; the plugin's own resizes reach the window.

### MCP attach mode

On Linux the editor serves attach mode on a Unix socket; on Windows it now
serves a named pipe, `\\.\pipe\venturi-<user>-mcp-<pid>.sock`. Remote clients
are refused and the pipe's default security admits only the current user.
`venturi mcp --attach` finds the running windows the same way as on Linux.

### OpenTimelineIO paths

Exported timelines used to write Windows paths as invalid URLs
(`file://C%3A%5C…`). They are now standard file URLs: `file:///C:/clips/a.mp4`,
and `file://server/share/a.mp4` for network shares, which import back to the
same paths. Timelines exported on Linux or macOS keep their paths.

## Tests

The whole workspace passes on Windows: about 1,600 tests, `cargo clippy
--all-targets -- -D warnings` and `cargo fmt --check`. New tests cover the
Windows parts: the plugin bundle layout, the Win32 editor window, the named
pipe server, D3D11VA decoding, the file URLs and the decoder order.

Tests that assumed Linux were made portable: plugin bundle layouts, file
times (Windows needs write access to change them) and path separators.

## CI and releases

`.github/workflows/ci.yml` gains a Windows job (clippy, the plugin, core and
MCP pipe tests) and `.github/workflows/release.yml` builds the Windows zip
next to the AppImages and the macOS dmg.

## Not covered yet

- No installer: the zip is portable, with no Start menu entry or `.vvproj`
  association.
- The executable is not code-signed.
- Plugin editors were tested with the bundled test plugin, not with
  commercial plugins.
